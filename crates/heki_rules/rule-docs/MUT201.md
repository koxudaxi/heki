## What it does
Checks writes to attributes and containers that a `[[tool.heki.write-owners]]` contract
reserves for a set of allowed writer functions. A write is reported when it happens outside the
allowed writers:

- directly (`model.fields = [...]`, `model.fields.append(...)`, `del model.fields`);
- through a local alias (`fields = model.fields; fields.append(...)`);
- through `setattr(model, "fields", ...)` / `object.__setattr__` or `model.__dict__["fields"]`;
- through a helper that mutates the container or object it receives (`helper(model.fields)`),
  reported once at the outermost call site.

A target names a class and an attribute; it covers the class's subclasses too (the target's
class family).

A private helper (`_name`) with project callers hands the responsibility to its callers: the
write is reported at the call sites of the first non-private callers, with the chain of calls
as related information.

A class's own initialization is allowed: a write inside an initializer (`__init__`,
`__post_init__`, `__new__`, `model_post_init`, `__setstate__`) of a class of the target's
family is not reported when the written object is the initializer's own `self`, whether it
writes it directly, through a local alias, through `super().__init__()`, or through helpers it
passes `self` to (`self._init_fields()`, `_setup(self)`). An object that may be `self`
(`self if flag else other`) gets the benefit of the doubt. Writes to objects that are provably
not `self` stay reported: another parameter, a fresh instance, an attribute of `self`.

## Why is this bad?
Large code bases often have one component that owns a piece of shared state (a store, a
registry, a cache). Writes from anywhere else bypass its invariants and make bugs that depend
on call order. The contract states the ownership once in configuration, with no runtime cost
and no decorators.

## Example
```toml
[[tool.heki.write-owners]]
name = "model-store"
targets = ["Model.fields"]
allowed-writers = ["Store.*"]
exempt-methods = ["__deepcopy__"]
message = "use Store.add_field() instead"
```

```python
class Model:
    def __init__(self) -> None:
        self.fields: list[str] = []  # allowed: the class's own initialization

    def __deepcopy__(self, memo: dict) -> "Model":
        new = Model()
        new.fields = list(self.fields)  # allowed: exempt method
        return new


class Store:
    def add_field(self, model: Model, name: str) -> None:
        model.fields.append(name)  # allowed writer


def parse(model: Model) -> None:
    model.fields.append("id")  # MUT201: outside `Store.*`
```

Use instead:
```python
def parse(model: Model, store: Store) -> None:
    store.add_field(model, "id")
```

## Fix safety
No automatic fix.

## Options
- `[[tool.heki.write-owners]]`:
  - `name`: the contract name, shown in messages.
  - `targets`: `Class.attr` entries; globs and dotted suffixes match (`Model.fields`,
    `pkg.model.Model.*`).
  - `allowed-writers`: functions allowed to write the targets, as dotted names or globs matched
    against the function's qualified name and its `Class.method` qualname (`Store.*`,
    `pkg.parser.generation.*`).
  - `exempt-methods`: construction and copy methods allowed to write the targets. A plain name
    (`__deepcopy__`, `copy_deep`) matches any function or method of that name; an entry with a
    dot or a glob (`Model.copy_deep`, `create_*`) is matched like `allowed-writers`. A write is
    allowed when any function on its chain (the writer and the private helpers between) is an
    allowed writer or an exempt method.
  - `message`: appended to every message of the contract (`use Store.add_field() instead`).
  - `forbid-cached-property-on`: classes on which a `@cached_property` is itself reported.
