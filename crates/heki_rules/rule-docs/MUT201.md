## What it does
Checks writes to attributes and containers that a `[[tool.heki.write-owners]]` contract
reserves for a set of allowed writer functions. A write is reported when it happens outside the
allowed writers:

- directly (`model.fields = [...]`, `model.fields.append(...)`, `del model.fields`);
- through a local alias (`fields = model.fields; fields.append(...)`), also one `getattr` with a
  constant name loads (`getattr(model, "fields").append(...)`), or what a method, property, or
  function returns when it returns the attribute itself on every `return`
  (`model.field_list().append(...)` with `return self.fields`), stores no attribute of that name
  itself, and every class the object may be runs it (no `cached_property`, no class attribute of
  the name coming first); the object must be passed by position (no keyword-only parameter, no
  `*args` unpacking);
- through `setattr(model, "fields", ...)` / `object.__setattr__` (also through a module-level
  name bound once to it: `_set = object.__setattr__`) or `model.__dict__["fields"]`,
  also with a string constant for the name (`model.__dict__[FIELDS_KEY]`, imported or not):
  a module-level name declared `Final` or bound once in its module and rebound by no other, or
  a class-body name declared `ClassVar` or `Final` and bound once (`self.KEY`, `cls.KEY`,
  `Model.KEY`), which every subclass of the object's class finds along its MRO in the same
  class (none defines it again or lists another base defining it first,
  `class Child(Other, Model)`) and no code stores on the class, a subclass, or an instance
  (`Model.KEY = "x"`; another module may store it on the defining class only for a `Final`
  one); on an instance of a protocol, every class implementing it must hold the same constant.
  A `Final` name of a dataclass (or of a class a `dataclass_transform` builds) is a field, which
  each instance holds itself (`Keys("x").KEY`): it names an attribute only when read on the
  class object of a dataclass whose default no class along the way replaces (one with
  `slots=True` or built by a transform);
- into the entries of the container the attribute holds (`model.meta["kw"][name] = v`,
  `model.meta["kw"].append(v)`, through a local alias of the entry): an `item_mut` write;
- through a helper that mutates the container or object it receives (`helper(model.fields)`),
  reported once at the outermost call site. A helper that sees the object's class (an annotated
  parameter, `self` of a method) reports its own write instead, so a write it routes through
  the allowed writers stays allowed for its callers; a helper handed the value of an attribute
  (`helper(field.data_type)`) writes that attribute only when it changes the value in place,
  and otherwise writes the value's own attributes. A helper that does not see the class and
  only hands the value on to an allowed writer or an exempt method writes inside the owner.

A target names a class and an attribute; it covers the class's subclasses too (the target's
class family). A target can also name one entry of the container an attribute holds,
`Class.attr["key"]`: it matches the writes of that key (`field.extras["init"] = v`,
`field.extras[INIT]` with a string constant, `field.extras.pop("init")`,
`del field.extras["init"]`, `field.extras["init"].append(v)`), not a write of the whole
container (`field.extras = {}`, `field.extras.update(...)`) or with a computed key, which are
writes of `Class.attr`. When a contract names both a container and one of its entries, a write of
the entry is reported once, under the entry.

The written object's class is the one heki infers for it, with annotations as hints: a
parameter, local, attribute, or return annotation, including the items of `list[...]`,
`Sequence[...]`, `Iterable[...]`, `Iterator[...]`, `Generator[...]`, `dict[...]`,
`Mapping[...]`, `tuple[...]`, and `set[...]`; a constructor call; and what the object comes
from: a loop over such a container (`for model in models`), a subscript (`models[0]`,
`by_name["a"]`), unpacking (`model, _ = pair`), `dict` views and `get` / `pop`, `enumerate`,
`zip`, `reversed`, `sorted`, `iter`, `next`, `list` / `tuple` / `set`, `itertools.chain`, a
display, the items appended to a local list, or a comprehension or generator expression. A
method call or a `@property` / `cached_property` read has the return annotation of the
definition the receiver's class finds first along its MRO, as for a type checker (`typing.Self`
is the receiver's class); a copy (`copy.copy`, `copy.deepcopy`, `dataclasses.replace`,
`model_copy`) has its original's class, calling a `functools.partial` object returns what the
wrapped function returns, and `typing.cast` names the class. A variable rebound in a loop
(`node = node.parent`) or assigned on some paths only (a walrus inside `and` / `or`) has the
classes of the values reaching it; a value of two or three classes (`Model | Node`, from an
annotation or from different assignments) is each of them, and an `isinstance` check narrows it
in the code it guards (`if isinstance(x, Model): ...`, `if not isinstance(x, Model): return`,
also inside `and` / `or`). A value typed with a project `Protocol` is an instance of the protocol
and of the project classes that implement it structurally (having every member it defines; at
most eight, counting a class and not its subclasses), also when it is handed to a helper that
does not type it: a target on the protocol and one on an implementation both cover its writes. An
object whose class heki cannot see (an unannotated parameter or return, `Any`, a value of more
than three classes, a protocol without members or with more implementations) is not tied to the
target.

A private helper (`_name`, or a comprehension, generator expression, or lambda scope) with
project callers hands the responsibility to its callers: the write is reported at the call
sites of the first non-private callers, with the chain of calls as related information. A
private function that only its own recursion calls (`_walk` calling itself, handed out as a
callback) has no such caller and reports its writes itself. One
report stands for every write behind that call (`sites` in JSON), so a Ratchet baseline counts a
second write inside a recorded helper. A write reached through an allowed writer on one path and
around it on another (or through a forbidden writer on one path only) is reported for the path
the contract does not allow.
Reading a `@property` or `functools.cached_property` attribute calls its getter, so a private
getter hands its writes to the functions reading it; a read never calls a property's setter.

A write runs where the body holding it runs. Calling a generator function only creates the
generator: its writes run where it is iterated (as for `EFF101`), so a generator created by an
allowed writer and iterated elsewhere writes elsewhere, and one handed to an allowed writer that
iterates it writes inside the owner. A generator that is created and never iterated writes
nothing. A coroutine that is never awaited or driven at a project call (handed to
`asyncio.create_task`, `ensure_future`, `gather`, ...) runs on the event loop: a private one
reports its own writes instead of handing them to the function that created it. Functions run on
another thread by an offloading decorator (`@sync_to_async`, ...) are not followed either.

A function that only runs inside the owner's operations is not reported either: it has project
callers, and every path of callers above it starts in an allowed writer, an exempt method, or
the class's own initialization (a mutator method that only the store and `__init__` call). A
function without project callers, one that is also called from anywhere else, or one reached
only through a cycle of other functions stays reported.

A class's own initialization is allowed: a write inside an initializer (`__init__`,
`__post_init__`, `__new__`, `model_post_init`, `__setstate__`) of a class of the target's
family is not reported when the written object is the initializer's own `self`, whether it
writes it directly, through a local alias, through `super().__init__()`, or through helpers it
passes `self` to (`self._init_fields()`, `_setup(self)`). An object that may be `self`
(`self if flag else other`) gets the benefit of the doubt. Writes to objects that are provably
not `self` stay reported: another parameter, an attribute of `self`.

A write that constructs the object it writes is allowed too (`fresh-objects = "allow"`, the
default): the object was allocated in the same call chain, by calling its class, by
`object.__new__(Model)` (also `Model.__new__(Model)` when no class defines `__new__`), by copying
(`copy.copy`, `copy.deepcopy`, `dataclasses.replace`, `.copy()`, `.model_copy()`), or by a
project function that returns such an object, and nothing else can hold it yet: no store into
another object, a container, a global, or a closure, no `yield`, and no call that may keep it
ran before the write. A project function keeps an object it stores, yields, or hands to code
heki does not follow or to a function that keeps it; reading or writing it keeps nothing. Writes
that a helper makes to a new object its caller hands it count as well. A shallow copy shares its
containers with the original, so only rebinding its attributes constructs it
(`copied.data_types = [...]`); `copied.data_types.append(x)` changes the original's list and is
reported. `fresh-objects = "report"` reports these writes like any other.

## What a report states

A report states that the function writes a target of a `write-owners` contract (an attribute, or the
container it holds) outside the contract's write owners, directly, through an alias, or through the
helpers shown.

Its premises:

- **Target**: the object is an instance of a class the contract names, or of a subclass, by
  construction or annotation (assumption R2). Open: an alias bound on one path is enough.
- **Outside the owners**: the function is not in the allowed modules and classes, nor runs only
  inside allowed contexts. Established from the contract.
- **Through helpers**: a helper's write, read, or call counts at its caller. Open: one path of the
  helper is enough.

## Why is this bad?
Large code bases often have one component that owns a piece of shared state (a store, a
registry, a cache). Writes from anywhere else bypass its invariants and make bugs that depend
on call order. The contract states the ownership once in configuration, with no runtime cost
and no decorators.

## Example
```toml
[[tool.heki.write-owners]]
name = "model-store"
targets = ["Model.fields"]
allowed-writers = ["Store.*"]
exempt-methods = ["__deepcopy__"]
message = "use Store.add_field() instead"
```

```python
class Model:
    def __init__(self) -> None:
        self.fields: list[str] = []  # allowed: the class's own initialization

    def __deepcopy__(self, memo: dict) -> "Model":
        new = Model()
        new.fields = list(self.fields)  # allowed: exempt method
        return new


class Store:
    def add_field(self, model: Model, name: str) -> None:
        model.fields.append(name)  # allowed writer


def parse(model: Model) -> None:
    model.fields.append("id")  # MUT201: outside `Store.*`
```

Use instead:
```python
def parse(model: Model, store: Store) -> None:
    store.add_field(model, "id")
```

## Options
- `[[tool.heki.write-owners]]`:
  - `name`: the contract name, shown in messages.
  - `targets`: `Class.attr` entries; globs and dotted suffixes match (`Model.fields`,
    `pkg.model.Model.*`).
  - `allowed-writers`: functions allowed to write the targets, as dotted names or globs matched
    against the function's qualified name and its `Class.method` qualname (`Store.*`,
    `pkg.parser.generation.*`). A module part names one module without its submodules:
    `pkg.model:*` allows what `pkg/model/__init__.py` defines, not `pkg.model.io.save`.
  - `forbidden-writers`: when set, only writes by these functions are reported (matched like
    `allowed-writers`, `pkg.render.*`); `allowed-writers` and `exempt-methods` stay exceptions
    inside them. A write is in scope when a function on its chain (the reporting function, the
    private helpers it hands the write through, or the writer) is forbidden.
  - `exempt-methods`: construction and copy methods allowed to write the targets. A plain name
    (`__deepcopy__`, `copy_deep`) matches any function or method of that name; an entry with a
    dot or a glob (`Model.copy_deep`, `create_*`) is matched like `allowed-writers`. A write is
    allowed when any function on its chain (the writer and the private helpers between) is an
    allowed writer or an exempt method.
  - `message`: the help of every report of the contract (`use Store.add_field() instead`).
  - `forbid-cached-property-on`: classes on which a `@cached_property` is itself reported.
  - `fresh-objects`: `"allow"` (default) or `"report"`: whether writes that construct the object
    they write are reported.
  - `unresolved`: `"ignore"` (default) or `"report"`: also report the writes the contract
    cannot tie to a class, under `MUT205`.
