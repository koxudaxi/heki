## What it does
Checks the de-duplication idiom `if v not in seen: seen.append(v)` inside a loop and suggests
keeping an auxiliary `set` next to the list.

Size-dependent: applied only with `--fix --include-size-dependent` or in profiled hot
functions.

## Why is this bad?
The membership test scans the list, so de-duplicating `n` items costs `n²` comparisons.

## Example
```python
def unique(values: list[int]) -> list[int]:
    seen = []
    for v in values:
        if v not in seen:
            seen.append(v)
    return seen
```

Use instead:
```python
def unique(values: list[int]) -> list[int]:
    seen = []
    seen_set = set()
    for v in values:
        if v not in seen_set:
            seen.append(v)
            seen_set.add(v)
    return seen
```

## Fix safety
Proven safe only when the list is an exact builtin list owned by the function, the paired
`append` is its only change inside the loop (a removal would make the set stale), no other live
reference could change it, and every element and probe is a hashable builtin scalar.
