## What it does
Checks reads of attributes that a `[[tool.heki.read-owners]]` contract reserves for a set of
allowed reader functions: the read side of `MUT201`. A read is reported when it happens outside
the allowed readers:

- directly (`ref.children`), also on `self` and through local aliases;
- through `getattr(ref, "children"[, default])` or `object.__getattribute__(ref, "children")`
  with a constant name;
- through `ref.__dict__["children"]` or `ref.__dict__.get("children")`.

A target names a class and an attribute; it covers the class's subclasses too.

A private helper (`_name`, or a comprehension, generator expression, or lambda scope) with
project callers hands the responsibility to its callers: the read is reported at every call
site of the first non-private callers above it, with the chain of calls as related
information. Reading a `@property` or `functools.cached_property` attribute calls its getter,
so a private getter (`ref._kids` returning `self.children`) hands its read to the functions
reading it. Reads in a class's own initializer on its own `self` are allowed, and so are reads
in a function that only runs inside allowed contexts (every path of callers above it starts in
an allowed reader or an exempt method), as for `MUT201`. One report stands for every read behind
its call (`sites` in JSON), as for `MUT201`.

## Why is this bad?
Some state is only meaningful through the component that maintains it: an index that keeps a
derived view consistent, a store that resolves references lazily. Reading the raw attribute
elsewhere sees stale or partial data, and the bug only shows up for some inputs. The contract
states which functions may read it once in configuration, with no runtime cost.

## Example
```toml
[[tool.heki.read-owners]]
name = "reference-children"
targets = ["Reference.children"]
allowed-readers = ["*GenerationIndex*"]
message = "read children through GenerationIndex instead"
```

```python
class Reference:
    def __init__(self) -> None:
        self.children: list["Reference"] = []


class GenerationIndex:
    def children_of(self, ref: Reference) -> list[Reference]:
        return list(ref.children)  # allowed reader


def _kids(ref: Reference) -> list[Reference]:
    return ref.children


def render(ref: Reference) -> str:
    return ", ".join(map(str, _kids(ref)))  # MUT203: reads `Reference.children` via `_kids`
```

Use instead:
```python
def render(ref: Reference, index: GenerationIndex) -> str:
    return ", ".join(map(str, index.children_of(ref)))
```

## Fix safety
No automatic fix.

## Options
- `[[tool.heki.read-owners]]`:
  - `name`: the contract name, shown in messages.
  - `targets`: `Class.attr` entries; globs and dotted suffixes match.
  - `allowed-readers`: functions allowed to read the targets, as dotted names or globs matched
    against the function's qualified name and its `Class.method` qualname.
  - `forbidden-readers`: when set, only reads by these functions are reported (matched like
    `allowed-readers`; `forbidden-readers = ["pkg.parser.*"]`: the parser layer must not read the
    targets); `allowed-readers` and `exempt-methods` stay exceptions inside them. A read is in
    scope when the reporting function or a private helper it hands the read through is
    forbidden.
  - `exempt-methods`: methods allowed to read the targets (`__repr__`, `__deepcopy__`); a plain
    name matches any function or method of that name, an entry with a dot or a glob is matched
    like `allowed-readers`.
  - `message`: appended to every message of the contract.

Known limitation: a read through a parameter without a project-class annotation
(`def helper(ref): return ref.children`) is not seen, since the read object's class is unknown.
