## What it does
Checks loops that run a database query on every iteration (the "N+1 queries" problem):
`cursor.execute(...)`, `session.execute(...)`, Django `QuerySet` methods, `pymongo` and `redis`
commands, and project functions that reach them.

It does not report DDL statements (`CREATE`, `ALTER`, `DROP`, `PRAGMA`), migration code
(`upgrade` / `downgrade` functions, files under `migrations/` or `alembic/`), the ORM packages'
own implementation, or bounded loops.

## Why is this bad?
One round trip per item makes the run time grow with the number of rows and with the network
latency to the database. A single batched query is usually orders of magnitude faster.

## Example
```python
def names(cursor, ids: list[int]) -> list[str]:
    out = []
    for i in ids:
        cursor.execute("SELECT name FROM users WHERE id = ?", (i,))  # EFF103
        out.append(cursor.fetchone()[0])
    return out
```

Use instead:
```python
def names(cursor, ids: list[int]) -> list[str]:
    marks = ",".join("?" * len(ids))
    cursor.execute(f"SELECT name FROM users WHERE id IN ({marks})", ids)
    return [row[0] for row in cursor.fetchall()]
```
