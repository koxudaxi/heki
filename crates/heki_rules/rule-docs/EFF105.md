## What it does
Checks `async def` functions that reach blocking local filesystem I/O: `open(...)`,
`pathlib.Path.read_text` / `write_text` / `read_bytes` / `write_bytes` / `open`, `os.listdir`,
`os.scandir`, `os.walk`, and `shutil` copies and removals. It follows the same boundary and
offload rules as `EFF101`.

This rule is opt-in: enable it with `--extend-select EFF105` or `extend-select = ["EFF105"]`.
Selecting the `EFF` prefix does not enable it.

## Why is this bad?
Local file I/O is usually fast, which is why it is opt-in, but on network file systems, large
files, or busy disks it blocks the event loop like any other blocking call.

## Example
```python
async def read_config(path: str) -> str:
    with open(path) as f:  # EFF105
        return f.read()
```

Use instead:
```python
import asyncio
from pathlib import Path


async def read_config(path: str) -> str:
    return await asyncio.to_thread(Path(path).read_text)
```

## Fix safety
No automatic fix.

## Options
- `lint.extend-select = ["EFF105"]` enables the rule.
- `lint.relax-async-in-tests` applies as for `EFF101`.
