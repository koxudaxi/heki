## What it does
Compares the interprocedural side effects of every public function with the summary snapshot
saved by `heki snapshot --write` (`.heki-summary-snapshot.json` at the project root), and reports
functions that gained one of:

- a mutated parameter (the function now changes an argument it receives);
- an escaping parameter (an argument is now stored in an attribute, a container, or a global);
- a mutated `self` attribute;
- an execution effect (blocking network / database / subprocess / filesystem I/O, sleeping,
  client allocation, database queries), including effects reached through callees.

This rule is opt-in: enable it with `--extend-select MUT103` or `extend-select = ["MUT103"]`.

## Why is this bad?
A pull request that makes a widely used helper start mutating its argument, or start doing
network I/O, often looks harmless in the diff of the helper and breaks callers far away. The
snapshot makes such effect regressions visible in review, the way a lock file makes dependency
changes visible.

## Example
```python
# snapshot taken while `add` was pure
def add(items: list[int], x: int) -> list[int]:
    return items + [x]
```

After an edit:
```python
def add(items: list[int], x: int) -> list[int]:  # MUT103: `add` now mutates parameter `items`
    items.append(x)
    return items
```

The report is on the function's `def` line, which is also where a suppression comment goes.

If the new effect is intended, refresh the snapshot with `heki snapshot --write` and commit it.

## Fix safety
No automatic fix.

## Options
- `lint.extend-select = ["MUT103"]` enables the rule.
- The snapshot lives at `.heki-summary-snapshot.json`; `heki snapshot` prints it without writing.
