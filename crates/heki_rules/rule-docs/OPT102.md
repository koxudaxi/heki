## What it does
Checks loops that rebuild a dict or set every iteration and rewrites them in place:

- `d = {**d, k: v}` → `d[k] = v`, or `d.update({...})` when the remaining entries have side
  effects;
- `d = {**d, **other}` → `d.update(other)`;
- `s = s | {e}` → `s |= {e}` (also `d = d | other` for dicts).

## What a report states

A report states that the merge (`{**d, ...}` with the accumulator first, `s = s | t`, `d = d |
other`) builds a new set or dict from the whole accumulated one on every iteration of the loop,
where updating it would change it in place.

Its premises:

- **Builtin set or dict**: the value is a builtin `set` or `dict` by its construction. Established:
  the Soundness lane takes types from constructions only.
- **Loop-carried**: the result is the accumulator of the next iteration. Established by the IR.
- **On every iteration**: the statement runs on every iteration of the loop. Open: a statement under
  a branch inside the loop counts.
- **Data-sized**: the code does not fix the sizes the cost depends on (the loop's and the
  container's) at 16 or fewer. Open: a size heki cannot bound counts as data-sized.
- **Rewrite proven safe**: the help says `[safe fix: ...]`, `[proven-safe suggestion: ...]`, or
  `[proven safe; ...]`. A report whose help names a blocking obligation instead (`[not auto-fixable:
  ...]`) lacks this premise and is heuristic whatever the rule's certainty; the proven reports are
  the rule's exact tier.

## Why is this bad?
Each rebuild copies the whole container, so the loop is quadratic. The in-place update is never
slower.

## Example
```python
def index(items: list[tuple[str, int]]) -> dict[str, int]:
    d = {}
    for k, v in items:
        d = {**d, k: v}
    return d
```

Use instead:
```python
def index(items: list[tuple[str, int]]) -> dict[str, int]:
    d = {}
    for k, v in items:
        d[k] = v
    return d
```

## Fix safety
Applied by `heki check --fix` only when proven safe, with the same obligations as `OPT101`
(exact builtin, unique, no live alias / iterator / view, evaluation order preserved), plus:

- the accumulator must be the leading `**` entry. `found = {**site, **found}` keeps the keys
  already in `found`, while `found.update(site)` would overwrite them, so it is never rewritten;
- for `|`, the right operand must be an exact `set` / `dict` (a subclass could make
  `__ror__` and `__ior__` disagree);
- the display inserts each entry before it evaluates the next one, and an insertion can run a
  key's `__eq__` (on a hash collision) or a mapping's `keys()` / `__getitem__`. Gathering
  several entries into one `d.update({...})` is applied only when the keys are `int` / `str` /
  `bytes` / `bool` / `float` values and the later entries are constants or local names;
  `d = {**d, **other}` with an unknown mapping `other` is not rewritten;
- an update that inserts several keys stops halfway when an insertion raises, where the display
  left `d` unchanged: it is not applied when an exception handler reads `d`.
