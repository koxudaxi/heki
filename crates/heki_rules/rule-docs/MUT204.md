## What it does
Checks calls of functions and methods, and constructions of classes, that a
`[[tool.heki.call-owners]]` contract reserves for a set of allowed callers: the call side of
`MUT201` (who may write) and `MUT203` (who may read). A call is reported when it happens outside
the allowed callers and resolves to a target:

- a method called on an instance of the target's class or of a subclass, including an override of
  the method in a subclass (`data_type.replace_reference(ref)`);
- the same method through a bound-method alias (`replace = data_type.replace_reference`, then
  `replace(ref)`) or `getattr(data_type, "replace_reference")(...)` with a constant name;
- a module-level function (`pkg.util.reset_cache()`);
- a class: constructing it or a subclass (`FinalFacts(...)`, `pkg.facts.FinalFacts(...)`,
  `cls(...)` in a class method), also for a dataclass or another class without an `__init__` of
  its own; with `subclasses = false`, constructing exactly the class.

A target ending in an argument list names only the calls passing those constants:
`DataType(is_dict=True)` is `DataType(is_dict=True)`, not `DataType(is_list=True)`, and
`container_flags(kind="dict")` is `container_flags(dt, "dict")`, not `container_flags(dt, "list")`.
A call passes a constant when heki establishes it: the argument is a literal, a string constant
bound once (a module's `Final` name), or a module's number or boolean bound once (`LIMIT = 0`),
also imported unless the importing module binds the name again (a `global` store or `del` in a
function, another module-level store, a star import), passed by keyword, by position where every function the call may run binds that position to the
parameter, or left out where every such function's default is `True`, `False`, `None`, `0`, or
`""` and the value. A keyword binds as Python binds it: never a positional-only parameter, and one
naming no parameter passes its value under its name into `**kwargs`. A call that raises
`TypeError` instead of running the function (a parameter bound by a position and a keyword, a
keyword without `**kwargs` to land in, a position past the parameters without `*args`) passes
nothing. A variable, a call result, `*` or `**` unpacking, or a position of a class without a
project `__init__` establishes nothing, and the call is not reported. A reference passes nothing,
so it never matches such a target.

With `references = "calls"` (or `"calls-and-bases"`), a reference handing a target on to be
called later counts as a call of it, reported where the target is named ("`f` hands on `pkg.core.decide`"; a name an import or
the module body binds is read without a position of its own, so it is reported at the statement
handing it on): passed to a call
(`partial(decide)`, `register(self.decide)`, `field(default_factory=Rule)`), stored in an
attribute, an item, or a global, returned, yielded, raised, or held by a display that is
(`[decide]`, `{"a": decide}`), also through an import alias (`from pkg.core import decide as
chosen`), a module alias (`run = core.decide`), or a module attribute (`core.decide`). A use that
only names a class is no reference: an argument of `isinstance`, `issubclass`, another builtin that
only inspects its arguments (`print`, `getattr`, `type`), `super`, `typing.cast`, `typing.TypeVar`,
`typing.NewType`, or `contextlib.suppress`; an `except` clause, a class's bases and keywords, a
function's defaults and annotations; a subscript (`Optional[Rule]`), a comparison (`f is decide`), a
receiver (`Rule.of(...)`), and a module binding another name to it. A callable a builtin calls once
per item (`sorted(xs, key=decide)`, `map(decide, xs)`) is a call already, and so is the
`functools.partial` object handed to one. A reference in a class body counts for the function
running the class statement (`<module>` for a class at module level).

With `references = "calls-and-bases"`, a class statement naming a class target among its bases
counts too ("`<module>` subclasses `pkg.core.Base`"): the class it makes holds the base, and
constructing it runs the base's initialization unless it overrides it. A base is a positional
argument of the class statement whose value is the class where the statement runs (`Base`,
`core.Base`, `Base[int]`, also through an import alias, a local alias, or a closure cell holding
it; a parameter, a local, or a class-body name of the imported class's name is another value),
matched as a construction is, so a base that is a subclass of the target counts unless
`subclasses = false`; a keyword (`metaclass=Base`) is no base. It is reported at the base where
the statement loads it, and at the class statement for a name an import or the module body
binds, for the function running the class statement (a nested class: the function running the
outer one).

A call through a value typed with a project `Protocol` that declares the method is judged by the
protocol's declaration (`h._helper()` with `h: Host` calls `Host._helper`), not by the
implementations it runs, and what an implementation's private method calls inside stays with it
(also when other callers call the method through the class and take its calls over).

A target's last segment names the function, method, or class: a glob there matches within that
name only (`pkg.*._*` is every private member in `pkg`, not every function of a private module,
and `pkg.api_*` is `pkg.api_commit`, not `pkg.api_helpers.api_reset`), and the report names the
function the call reaches.

A call is reported only when every function it may call is a target: when the receiver's class
hierarchy also offers a method that is no target (a receiver typed with a base class whose own
`replace_reference` is not guarded), the call is not reported. The functions it may call can be
targets of different entries of one contract: with `A.reset` and `B.reset` both listed, `obj.reset()`
on `obj: Base`, whose subclasses `A` and `B` implement `reset`, is one report for
`A.reset|B.reset`. A call on a receiver whose class heki does not know (an unannotated
parameter, `Any`) is not seen; with `unresolved = "report"`,
`MUT207` reports it.

A private helper (`_name`, or a comprehension, generator expression, or lambda scope) with project
callers hands its calls to its callers: the call is reported at the call sites of the first
non-private callers, with the chain of calls down to the call as related information. A call runs
where the body holding it runs, as for `MUT201`: a generator's calls where it is iterated (a
generator an allowed caller creates and returns calls outside it when its caller iterates it), a
coroutine's where it is awaited. Not reported either:

- a function that only runs inside allowed callers: it has project callers, and every path of
  callers above it starts in an allowed caller, an exempt method, or a class's own
  initialization (as for `MUT201`);
- a class's own initialization: an initializer (`__init__`, `__post_init__`, ...) of a class of
  the target's family calling a guarded method on its own `self`, or handing it on with
  `references = "calls"`, directly or through a private helper (for a target naming no class,
  `reset`, the family is the classes defining the methods it names and their subclasses);
- a target calling a target of the same contract (`remove_reference` calling
  `self.replace_reference(None)`, an override calling `super().replace_reference(...)`): the
  guarded operation is checked where it is called, so what it does inside is part of it.

With `attribution = "lexical"`, a call is judged in the function whose code holds it instead: a
private helper reports its calls itself, and a function that only runs inside allowed callers
is reported too. A lambda, comprehension, or generator expression is part of the function it is
written in (`any(decide() for x in xs)` in an allowed function is allowed), and a nested `def`
is a function of its own. A class's own initialization and the targets calling each other stay
allowed.

## What a report states

A report states that the function calls a function or method, or constructs a class, that a
`call-owners` contract reserves, outside the contract's call owners; with `references = "calls"`,
that it hands one on; with `references = "calls-and-bases"`, also that it subclasses one.

Its premises:

- **Target**: the receiver or the callee is an instance of a class the contract names, or of a
  subclass, by construction or annotation (assumption R2). Open: an alias bound on one path is
  enough.
- **Outside the owners**: the function is not in the allowed modules and classes, nor runs only
  inside allowed contexts (with `attribution = "lexical"`: the function holding the call is not
  allowed). Established from the contract.
- **Through helpers**: a helper's write, read, or call counts at its caller (never with
  `attribution = "lexical"`). Open: one path of the helper is enough.
- **Hands on** (`references = "calls"`): the value named is the target, and it reaches, through
  copies and displays, an argument, a store, a `return`, a `yield`, or a `raise`. Open: a value
  merged from several paths is enough. Whether the code it is handed to calls it is not part of
  the claim.
- **Subclasses** (`references = "calls-and-bases"`): the value the class statement passes as a
  base is the target class, typed where the statement runs. Established: a base heki cannot type
  (a parameter, a call's result, a value merged from paths that disagree) is no match. Whether
  the subclass is constructed is not part of the claim.
- **Arguments** (a target with an argument list): the call binds each parameter the list names to
  its constant, as Python binds the call. Established: an argument heki cannot tell is no match,
  and a call that raises `TypeError` instead of running the function binds nothing.

## Why is this bad?
Some operations keep invariants only when one component runs them: a store that updates its
indexes after redirecting a reference, a factory that builds a sealed object exactly once. A
direct call from elsewhere skips the bookkeeping, and nothing fails until an input exercises the
stale state. A linter cannot tell `data_type.replace_reference(ref)` from `text.replace("a", "b")`
without the receiver's class, and an import rule cannot forbid a method of an object the caller
legitimately imports. The contract states the ownership once in configuration.

## Example
```toml
[[tool.heki.call-owners]]
name = "reference-mutators"
targets = ["DataType.replace_reference", "FinalFacts"]
allowed-callers = ["pkg.store.GenerationStore.*"]
message = "use a GenerationStore operation instead"
```

```python
# pkg/store.py
class GenerationStore:
    def replace_data_type_ref(self, data_type: DataType, ref: Reference) -> None:
        data_type.replace_reference(ref)  # allowed caller


def swap(data_type: DataType, ref: Reference) -> None:
    data_type.replace_reference(ref)  # MUT204: outside `pkg.store.GenerationStore.*`


def rename(text: str) -> str:
    return text.replace("a", "b")  # not reported: a `str`, not a `DataType`
```

Use instead:
```python
def swap(store: GenerationStore, data_type: DataType, ref: Reference) -> None:
    store.replace_data_type_ref(data_type, ref)
```

## Options
- `[[tool.heki.call-owners]]`:
  - `name`: the contract name, shown in messages.
  - `targets`: functions, methods, or classes, as dotted names or globs matched against the fully
    qualified name and any dotted suffix (`DataType.replace_reference`, `pkg.util.reset_cache`,
    `FinalFacts`, `Parser._*`). A `Class.method` target covers the method's overrides in
    subclasses; a class target covers constructing the class and its subclasses; a target
    naming no class (`reset`) covers every project function and method of that name. A target
    may end in an argument list of `parameter=value` entries (`DataType(is_dict=True)`), each
    value `True`, `False`, `None`, an integer, or a quoted string.
  - `allowed-callers`: functions allowed to call the targets, as dotted names or globs matched
    against the function's qualified name and its `Class.method` qualname (`pkg.store.*`). A
    module part names one module without its submodules: `pkg:*` allows what `pkg/__init__.py`
    defines, not `pkg.sub.user.sub_user`.
  - `forbidden-callers`: when set, only calls by these functions are reported (matched like
    `allowed-callers`); `allowed-callers` and `exempt-methods` stay exceptions inside them. A
    call is in scope when the reporting function or one of the private helpers it hands the call
    through is forbidden (`forbidden-callers = ["pkg.parser.*"]`: the parser layer must not call
    the targets).
  - `exempt-methods`: methods allowed to call the targets (`__deepcopy__`); a plain name matches
    any function or method of that name, an entry with a dot or a glob is matched like
    `allowed-callers`.
  - `message`: the help of every report of the contract.
  - `unresolved`: `"ignore"` (default) or `"report"`: also report the calls the contract cannot
    tie to a class, under `MUT207`.
  - `references`: `"ignore"` (default), `"calls"`, or `"calls-and-bases"`: a reference handing
    a target on to be called later counts as a call of it, and with `"calls-and-bases"` a class
    statement naming a class target among its bases too.
  - `attribution`: `"call-graph"` (default) or `"lexical"`: whether a private helper hands its
    calls to its callers and a function that only runs inside allowed callers is allowed, or
    each call is judged in the function holding it.
