## What it does
Checks `async def` functions that reach a blocking call on the event loop, directly or through
synchronous helpers: network I/O (`requests`, `httpx.Client`, `urllib`), database drivers
(`sqlite3`, `psycopg`, `pymongo`, ...), subprocesses waiting for completion, `time.sleep`, and
other blocking synchronization.

Reading a `@property` or `functools.cached_property` attribute of a project class runs its
getter, so the read counts as a call of the getter (`self.client` whose getter opens a
connection). A property that also defines a setter or deleter is not followed.

The rule reports the boundary: the call (or property read) inside the `async def` that leads to
the blocking operation, with the call chain as related information. Several boundaries reaching
the same blocking call are grouped once ten or more of them exist.

It does not report:

- calls offloaded to a thread (`asyncio.to_thread`, `loop.run_in_executor`,
  `anyio.to_thread.run_sync`, `run_in_threadpool`, and project wrappers that forward their
  callable to them);
- `async` APIs, also where they are not awaited directly (`async with`, `asyncio.gather`,
  `asyncio.wait_for`): `httpx.AsyncClient`, `aiohttp`, `redis.asyncio`, SQLAlchemy's
  `AsyncSession`, psycopg's `AsyncConnection`, pymongo's `AsyncMongoClient`, ...;
- clients that connect on first use (`redis.Redis(...)`, `pymongo.MongoClient(...)`,
  `sqlalchemy.create_engine(...)`) and calls that only build an object (`Redis.pipeline()`, a
  lazy Django `QuerySet.filter(...)`): the call that does the I/O is the one reported;
- spawning a process without waiting (`subprocess.Popen(...)`);
- coroutine functions that only run through a synchronous driver (`asyncio.run`, ...);
- CLI commands (`@click.command`, `@app.command`), ASGI lifespan handlers, and tests
  (`test_*` functions and files under `tests/`, see the option below).

## Why is this bad?
A blocking call inside a coroutine stops the whole event loop: every other request, timer, and
task waits until it returns.

## Example
```python
import time


def load() -> bytes:
    time.sleep(1)
    return b""


async def handler() -> bytes:
    return load()  # EFF101: reaches `time.sleep`
```

Use instead:
```python
import asyncio


async def handler() -> bytes:
    return await asyncio.to_thread(load)
```

## Fix safety
No automatic fix.

## Options
- `lint.relax-async-in-tests` (default `true`): skip test code.
- `[[tool.heki.ecosystem]]` declares project functions as blocking (`effects`), as offload
  wrappers (`offloads-blocking-arg`), or as async-safe (`async-safe`).
