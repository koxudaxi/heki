## What it does
Checks for a single-pass iterator or generator that is consumed a second time. Once an
iterator is exhausted, every further pass over it sees no items, silently.

Single-pass values are:

- generator expressions (`(x for x in xs)`);
- `iter`, `zip`, `map`, `filter`, `enumerate`, `reversed`, and the single-pass `itertools`
  functions (`chain`, `islice`, `starmap`, `takewhile`, `dropwhile`, `filterfalse`,
  `compress`, `accumulate`, `groupby`, `pairwise`, `batched`, `zip_longest`, `product`,
  `permutations`, `combinations`, `combinations_with_replacement`), resolved through imports
  so a shadowed name is never matched;
- calls of project generator functions (from any module);
- parameters and locals annotated `Iterator`, `Generator`, `AsyncIterator`, or
  `AsyncGenerator` (`typing` or `collections.abc`; `Iterable`, `Sequence`, and `Collection`
  may be re-iterable and are not tracked).

A value is consumed by a `for` loop or comprehension over it, `yield from`, `list`, `tuple`,
`set`, `frozenset`, `dict`, `sum`, `any`, `all`, `min`, `max`, `sorted`, `str.join`, a wrapper
that is itself consumed (`enumerate(it)`, `map(f, it)`, `chain(it, other)`, `zip(it, it)`, a
generator expression over it, ...), or a project function that iterates the parameter it is
passed to exhaustion. `next(it)` and `len` are not consumptions, and neither is `zip` / `map`
over several iterables: they stop at the shortest one (`zip(range(n), it)` takes `n` items).

The rule reports the second pass when the first one runs to exhaustion and the second is
reachable from it, without rebinding the variable in between. It also reports a value created
outside a loop and consumed to exhaustion inside it: the next iteration sees nothing.

It does not report:

- a first pass that may stop early: a `for` loop with `break`, `return`, or `raise` inside
  (`it = iter(lines)`, then `for line in it: ... break`, then `for line in it:` is the
  idiomatic way to resume);
- passes on exclusive branches (`if c: list(it) else: sorted(it)`);
- a variable rebound to a fresh iterator in between;
- `itertools.tee` results, `repeat`, `cycle`, and `count`;
- loops that run at most once (`for _ in range(1)`), and a consumption followed by leaving the
  loop (`data = list(it)` then `break`);
- consuming the rest of an iterator inside a loop over that iterator itself.

## Why is this bad?
The second pass silently gets an empty iterator: totals become zero, a second report is empty,
and a retry processes nothing. Nothing fails, so the bug is noticed far away from its cause.

## Example
```python
def summarize(lines: list[str]) -> tuple[int, list[str]]:
    rows = (line.strip() for line in lines)
    count = sum(1 for _ in rows)
    kept = [r for r in rows if r]  # MUT106: `rows` was consumed by `sum`
    return count, kept
```

Use instead:
```python
def summarize(lines: list[str]) -> tuple[int, list[str]]:
    rows = [line.strip() for line in lines]  # a list can be iterated any number of times
    count = len(rows)
    kept = [r for r in rows if r]
    return count, kept
```

## Fix safety
No automatic fix.

## Options
- `lint.extend-select = ["MUT106"]` (or `--extend-select MUT106`) enables the rule. It is
  opt-in: selecting the `MUT` prefix does not enable it.
