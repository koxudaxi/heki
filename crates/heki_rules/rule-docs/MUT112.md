## What it does
Checks for a container that is a new object on one path and borrowed state on another, and that
is then changed in place. The rule is opt-in: enable it with `--extend-select MUT112` or
`extend-select = ["MUT112"]`.

A value is a new object where the function makes it: a display (`[]`, `{}`), a comprehension, a
copy (`list(x)`, `dict(x)`, `x.copy()`, `copy.copy`), a constructor call, an operator's result
(`a + b`), or a call of a project function that returns a new object. It is borrowed where it
comes from state that outlives the call: a parameter, an attribute, a global, a variable of an
enclosing function, an element of one of these, or a call of a project function that returns
such state. The paths meet in a conditional expression or an `if`:

- `items = given or []`, `items = given if given else []`;
- `options = dict(defaults, **extra) if extra else defaults`;
- `seen = registry.get(key, {})`, `tags = getattr(obj, "tags", [])`;
- `x = shared`, then `if c: x = []`.

What a project function returns is part of its summary, through any number of wrappers: a
function that returns its argument on one path and a new object on another makes its call's
result both when the caller passes borrowed state, and one returning an attribute it caches
makes its call's result borrowed. Only the returns a run can reach count: a `return` after a
`while True:` loop that no `break` leaves, or under `if False:`, returns nothing.

A change is an item assignment or deletion, a container method (`append`, `extend`, `update`,
`setdefault`, `pop`, ...), an in-place operator on a `list`, `dict`, `set`, or `bytearray`, or a
call of a project function that changes the container it is handed. The rule reports the first
change of the value in the function. It also reports:

- a change made by a closure to a variable of the enclosing function that holds such a value;
- a store of such a value in `self.<attr>` when a method of the class, of a subclass, or of a
  base class changes that attribute in place (`self.items.append(x)`, through an alias, or
  through a helper), at the store.

It does not report:

- a value that is a new object on every path, or borrowed on every path;
- a value rebound to a copy before the change (`x = list(x)`), also when the copy is made only
  where the value is still the borrowed object (`if x is shared: x = shared.copy()`);
- the accumulator idiom, where a parameter is replaced by a new object only when it is `None`
  or a sentinel (`if out is None: out = []`, `out = [] if out is None else out`): the function
  fills what its caller hands it. Such a value counts when it may also be a new object the test
  does not select (`x = [] if fresh else out` after it), and when it is also stored on `self`,
  where the instance keeps the caller's object. A test that replaces nothing (`if out is None:
  raise ...`) leaves the parameter borrowed;
- a new object the function stores in other state before the paths meet
  (`rows = table[key] = []`, `table.setdefault(key, rows)`): it is that state's on every path;
- a value stored back where it borrows from, the same attribute of the same object or an item
  of the same container (`self.items = self.items or []`, `d[k] = d.get(k) or []`, but not
  `self.items = other.items or []`);
- attributes named as memos or caches (`_cache`, `memo`), which are meant to be filled;
- removing from a value whose new objects all start empty (`d.get(k, {}).pop(x, None)`): the
  removal does nothing to them;
- a conditional expression changed in place without a name (`(a if c else b).append(x)`): the
  code picks the container on purpose;
- attribute assignments, and changes of a value below the borrowed one (`x[0].append(1)`): a
  copy of `x` shares those too;
- `self` in its own methods, and paths a branch on a constant never takes (`while True:`).

## Why is this bad?
The function treats the value as its own on one path and changes a shared object on the other.
The caller's list, a cached dictionary, or a class attribute changes only when the borrowed path
runs, for example only when the caller passes a non-empty list, so the bug shows up far away and
on some inputs only.

## Example
```python
def collect(name: str, scopes: list[str] | None = None) -> list[str]:
    use_scopes = scopes or []
    use_scopes.extend(lookup(name))  # MUT112: changes the caller's list when it is not empty
    return use_scopes
```

Use instead:
```python
def collect(name: str, scopes: list[str] | None = None) -> list[str]:
    use_scopes = list(scopes or [])
    use_scopes.extend(lookup(name))
    return use_scopes
```

## Known limitations
- The paths are not told apart by the tests on them: a value that an `if v is SENTINEL: return`
  excludes, or a callee that returns its argument only when it is not a container, still counts.
- Calls of `async def` functions and generators are not followed: their results are not what
  their bodies return.
- A store in an attribute is followed for `self` only.

## Fix safety
No automatic fix.

## Options
- `lint.extend-select = ["MUT112"]` enables the rule.
