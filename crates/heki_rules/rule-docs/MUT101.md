## What it does
Checks for methods that rebind or mutate an attribute that a `@functools.cached_property`
of the same class (or of a subclass) reads, without invalidating the cached value.

## Why is this bad?
A `cached_property` computes its value once and stores it in the instance `__dict__`. Once the
attribute it was computed from changes, the property keeps returning the old value until the
cache entry is deleted. The stale value is usually noticed far away from the write.

The rule follows `self.helper()` calls in both directions (a property that reads through a
helper, a method that writes through a helper) and reports the write itself, once per property.
It does not report:

- two-phase initialization: `__init__`, `__post_init__`, `model_post_init`, `__setstate__`,
  `__enter__`, `setup`, `_init_*` / `_configure_*` methods, and private helpers called from
  `__init__`;
- memo / cache dictionaries (`self._cache[key] = value`, `setdefault`, the
  `if key not in self._memo:` pattern);
- constant dictionary keys the property never reads (`self.params["proxy"]` while the property
  reads `self.params["outtmpl"]`);
- private helpers whose every caller invalidates the property.

## Example
```python
from functools import cached_property


class Settings:
    def __init__(self, raw: dict[str, str]) -> None:
        self.raw = raw

    @cached_property
    def keys(self) -> tuple[str, ...]:
        return tuple(self.raw)

    def replace(self, raw: dict[str, str]) -> None:
        self.raw = raw  # `self.keys` still returns the old keys
```

Use instead:
```python
    def replace(self, raw: dict[str, str]) -> None:
        self.raw = raw
        self.__dict__.pop("keys", None)  # or `del self.keys` when it was computed
```

## Fix safety
No automatic fix: whether to invalidate, recompute, or make the attribute read-only is a design
decision.
